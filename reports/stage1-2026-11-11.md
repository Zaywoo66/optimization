# Этап 1: замер на текущем ПК

Дата: 11 ноября 2026 года. Windows 11 Pro, сборка 26200; AMD Ryzen 7 7435HS, 8 физических ядер / 16 потоков; 11,7 ГиБ ОЗУ; системный диск Micron MTFDKCD512QFM-1BD1AABLA, SSD/NVMe.

Команда: `memory-pilot report 10`. Во время двух 10-секундных прогонов шла работа Codex над проектом, но тяжёлой компиляции или воспроизводимого зависания не было. Это **не** замер худшего сценария пользователя.

| Показатель | Прогон 1 | Прогон 2 |
| --- | ---: | ---: |
| CPU, среднее | 12,7% | 12,1% |
| Commit / limit, среднее | 80,1% | 80,0% |
| Доступная ОЗУ, минимум | 2918,6 МиБ | 2861,5 МиБ |
| Page Reads/sec, среднее | 48,1 | 3,8 |
| Pages Input/sec, среднее | 553,1 | 32,0 |
| Очередь физического диска, среднее | 0,1 | 0,2 |
| Занятость диска, среднее | 14,1% | 17,0% |
| Foreground WM_NULL p95/p99 | 0,2 / 0,2 мс | 51,8 / 51,8 мс |
| Пробы, достигшие тайм-аута | 0 | 0 |
| Сэмплер: CPU, среднее от всего ПК | 0,1% | 0,1% |
| Сэмплер: пик RAM | 16,1 МиБ | 15,9 МиБ |
| Сэмплер: I/O за 10 с | 1720,6 КиБ | 1729,3 КиБ |

Вывод: в этих коротких прогонах устойчивого насыщения CPU или очереди диска не видно; доступно почти 3 ГиБ ОЗУ. Commit около 80% лимита сам по себе не доказывает нехватку физической памяти. Разброс page reads показывает, что нужен повтор в момент реального лага. Снижение задержки/ресурсов **не проверялось**, потому что этап 1 не применяет никаких изменений.

`WM_NULL` измеряет ответ оконного цикла выбранного foreground-окна. Он не равен полной задержке ввода пользователя. `Page Reads/sec` — операции чтения для разрешения hard faults, `Pages Input/sec` — число считанных страниц, а не число отдельных faults.
